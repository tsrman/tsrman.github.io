API для сторонних разработчиков

Начиная с Car Rules Voice v1.29 любое другое приложение на том же устройстве может: 1) получить список сохранённых правил и 2) запустить конкретное правило по требованию — например, из своего собственного триггера, кнопки на экране или интеграции с другим сервисом. Это открытая нативная Android IPC (Content Provider + Broadcast), не веб-API — работает только на том же устройстве, между установленными приложениями.

Важно: запуск правила выполняет его действия по-настоящему — включая управление автомобилем (окна, зеркала, багажник и т.д.), если правило это делает. Условия и геозона правила при внешнем запуске не проверяются — ведёт себя как нажатие кнопки «▶ Запустить» в приложении.

1. Разрешение

Оба механизма защищены одним и тем же разрешением уровня normal — такое разрешение не требует диалога с пользователем при установке, но вызывающее приложение обязано объявить его в своём AndroidManifest.xml:

<uses-permission android:name="org.tsrman.carrules.voice.permission.RUN_RULE" />

2. Получить список правил

Content Provider, метод call() (не таблица/Cursor — просто JSON-строка в ответе):

Authorityorg.tsrman.carrules.voice.rules
МетодlistRules
Ключ ответаrules_json — строка с JSON-массивом
val uri = Uri.parse("content://org.tsrman.carrules.voice.rules")
val json = contentResolver.call(uri, "listRules", null, null)
    ?.getString("rules_json")
// json, например: [{"id":"3f2a...","name":"Открыть окна","enabled":true}, ...]

В ответе — только id, name и enabled каждого правила: этого достаточно, чтобы выбрать, что запускать. Триггеры/условия/действия правила наружу не отдаются. Если разрешение не выдано — метод вернёт null.

3. Запустить правило

Явный broadcast (без intent-filter — компонент нужно указывать по имени, обычная рассылка на этот приёмник система не доставит):

Компонентorg.tsrman.carrules.voice/com.seres.carrules.RunRuleReceiver
Extra rule_idid правила (из списка выше) — имеет приоритет, если задан
Extra rule_nameточное имя правила — если id неизвестен
val intent = Intent()
intent.component = ComponentName(
    "org.tsrman.carrules.voice", "com.seres.carrules.RunRuleReceiver"
)
intent.putExtra("rule_name", "Открыть окна")  // или "rule_id" с UUID
sendBroadcast(intent)

Через adb (для проверки без написания кода):

adb shell am broadcast -n org.tsrman.carrules.voice/com.seres.carrules.RunRuleReceiver \
  --es rule_name "Открыть окна"

Запуск — «выстрелил и забыл»: приёмник ничего не возвращает вызывающему приложению. Если правило с таким id/именем не найдено, Car Rules Voice запишет об этом строку в собственный журнал (виден только в самом приложении).

Итого: что нужно вызывающему приложению

  1. Объявить <uses-permission android:name="org.tsrman.carrules.voice.permission.RUN_RULE" />.
  2. (Опционально) запросить список правил через content-provider, чтобы получить их id/имена.
  3. Отправить explicit broadcast на RunRuleReceiver с rule_id или rule_name.

Требуется Car Rules Voice v1.29 или новее — в более старых версиях ни приёмника, ни провайдера ещё нет.

Developer API

Starting with Car Rules Voice v1.29, any other app on the same device can: 1) list the saved rules, and 2) run a specific rule on demand — e.g. from its own trigger, a button in its UI, or an integration with another service. This is plain native Android IPC (a Content Provider + a Broadcast), not a web API — it only works on the same device, between installed apps.

Important: running a rule actually executes its actions — including controlling the vehicle (windows, mirrors, tailgate, etc.) if the rule does that. A rule's conditions and geofence are not evaluated for an external run — it behaves exactly like tapping the app's own "▶ Run" button.

1. Permission

Both mechanisms are gated by the same normal-protection-level permission — it needs no install-time dialog, but the calling app must still declare it in its own AndroidManifest.xml:

<uses-permission android:name="org.tsrman.carrules.voice.permission.RUN_RULE" />

2. List the rules

A Content Provider, using call() (not a table/Cursor — just a JSON string in the reply):

Authorityorg.tsrman.carrules.voice.rules
MethodlistRules
Reply keyrules_json — a JSON array as a string
val uri = Uri.parse("content://org.tsrman.carrules.voice.rules")
val json = contentResolver.call(uri, "listRules", null, null)
    ?.getString("rules_json")
// json, e.g.: [{"id":"3f2a...","name":"Open windows","enabled":true}, ...]

The reply carries only each rule's id, name and enabled flag — enough to pick what to run. A rule's triggers/conditions/ actions are not exposed. If the permission isn't granted, the call returns null.

3. Run a rule

An explicit broadcast (no intent-filter — it must be targeted by component name; a plain broadcast won't reach this receiver):

Componentorg.tsrman.carrules.voice/com.seres.carrules.RunRuleReceiver
Extra rule_idthe rule's id (from the list above) — takes priority if given
Extra rule_namean exact rule name — for when the id isn't known
val intent = Intent()
intent.component = ComponentName(
    "org.tsrman.carrules.voice", "com.seres.carrules.RunRuleReceiver"
)
intent.putExtra("rule_name", "Open windows")  // or "rule_id" with a UUID
sendBroadcast(intent)

Over adb (for testing without writing code):

adb shell am broadcast -n org.tsrman.carrules.voice/com.seres.carrules.RunRuleReceiver \
  --es rule_name "Open windows"

The run is fire-and-forget: the receiver returns nothing to the caller. If no rule matches the given id/name, Car Rules Voice logs a line about it in its own journal (visible only inside the app itself).

Summary: what a caller needs

  1. Declare <uses-permission android:name="org.tsrman.carrules.voice.permission.RUN_RULE" />.
  2. (Optional) query the content provider to learn the rules' ids/names.
  3. Send an explicit broadcast to RunRuleReceiver with rule_id or rule_name.

Requires Car Rules Voice v1.29 or newer — older versions have neither the receiver nor the provider.

API برای توسعه‌دهندگان

از نسخهٔ Car Rules Voice v1.29 به بعد، هر برنامهٔ دیگری روی همان دستگاه می‌تواند: ۱) فهرست قوانین ذخیره‌شده را دریافت کند و ۲) یک قانون مشخص را در هر زمان اجرا کند — مثلاً از محرک خودش، یک دکمه در رابط کاربری‌اش، یا یکپارچه‌سازی با سرویسی دیگر. این یک IPC ساده و بومی اندروید (یک Content Provider + یک Broadcast) است، نه یک API وب — فقط روی همان دستگاه، بین برنامه‌های نصب‌شده کار می‌کند.

مهم: اجرای یک قانون واقعاً اقدامات آن را انجام می‌دهد — از جمله کنترل خودرو (شیشه‌ها، آینه‌ها، درب صندوق و غیره) اگر قانون چنین کاری انجام دهد. شرط‌ها و ژئوفنس قانون برای اجرای خارجی بررسی نمی‌شوند — دقیقاً مانند فشردن دکمهٔ «▶ اجرا» در خود برنامه عمل می‌کند.

۱. مجوز

هر دو مکانیزم با یک مجوز با سطح حفاظت normal کنترل می‌شوند — این مجوز نیازی به پنجرهٔ تأیید هنگام نصب ندارد، اما برنامهٔ فراخواننده باید آن را در AndroidManifest.xml خودش اعلام کند:

<uses-permission android:name="org.tsrman.carrules.voice.permission.RUN_RULE" />

۲. دریافت فهرست قوانین

یک Content Provider، با استفاده از call() (نه یک جدول/Cursor — فقط یک رشتهٔ JSON در پاسخ):

Authorityorg.tsrman.carrules.voice.rules
متدlistRules
کلید پاسخrules_json — یک آرایهٔ JSON به‌صورت رشته
val uri = Uri.parse("content://org.tsrman.carrules.voice.rules")
val json = contentResolver.call(uri, "listRules", null, null)
    ?.getString("rules_json")
// json, e.g.: [{"id":"3f2a...","name":"Open windows","enabled":true}, ...]

پاسخ فقط شامل id، name و وضعیت enabled هر قانون است — همین برای انتخاب اینکه چه چیزی اجرا شود کافی است. محرک‌ها/شرط‌ها/اقدامات یک قانون افشا نمی‌شوند. اگر مجوز داده نشده باشد، فراخوانی null برمی‌گرداند.

۳. اجرای یک قانون

یک broadcast صریح (بدون intent-filter — باید با نام کامپوننت هدف‌گذاری شود؛ یک broadcast معمولی به این receiver نمی‌رسد):

کامپوننتorg.tsrman.carrules.voice/com.seres.carrules.RunRuleReceiver
Extra با کلید rule_idشناسهٔ قانون (از فهرست بالا) — در صورت وجود، اولویت دارد
Extra با کلید rule_nameنام دقیق قانون — وقتی شناسه مشخص نیست
val intent = Intent()
intent.component = ComponentName(
    "org.tsrman.carrules.voice", "com.seres.carrules.RunRuleReceiver"
)
intent.putExtra("rule_name", "Open windows")  // یا "rule_id" با یک UUID
sendBroadcast(intent)

از طریق adb (برای آزمایش بدون نوشتن کد):

adb shell am broadcast -n org.tsrman.carrules.voice/com.seres.carrules.RunRuleReceiver \
  --es rule_name "Open windows"

اجرا به‌صورت «شلیک و فراموش» است: receiver چیزی به فراخواننده برنمی‌گرداند. اگر قانونی با آن id/نام یافت نشود، Car Rules Voice خطی دربارهٔ آن در گزارش داخلی خودش ثبت می‌کند (فقط داخل خود برنامه قابل مشاهده است).

خلاصه: چه چیزی برای فراخواننده لازم است

  1. اعلام <uses-permission android:name="org.tsrman.carrules.voice.permission.RUN_RULE" />.
  2. (اختیاری) درخواست از content provider برای دریافت id/نام قوانین.
  3. ارسال یک broadcast صریح به RunRuleReceiver با rule_id یا rule_name.

نیازمند Car Rules Voice نسخهٔ ۱٫۲۹ یا جدیدتر است — نسخه‌های قدیمی‌تر نه این receiver را دارند و نه آن provider را.
