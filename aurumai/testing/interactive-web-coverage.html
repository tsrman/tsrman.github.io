Interactive questions and web coverage

Test presence, an isolated unit pass and a full live wrapper pass are different claims. Release reports identify the candidate and actual runtime/provider tested. Private incident data and historical recovery journals are not public release assets.

Run sequentially with other organization-mutating/browser acceptance. Provide matching application/web/search secrets before mutation. Trace/video/screenshots/ storage state are disabled; the dedicated web harness sanitizes matcher diagnostics.

Kubernetes browser traffic uses Helm Ingress through loopback k3d NodePort30080. Workload/CNI controls stay dual-stack; disabling the system service load balancer is not permission to drop IPv6 tests. REST-only recovery forwards exist solely for compatible established recovery paths, not browser SSE transport.

Recovery and honest status

PASS requires the complete scenario, exact Temporal/resource cleanup, permission restoration, verify-clean, teardown and infrastructure verification. A partial browser pass or cleanup-only recovery does not close a gate. Preserve journals/ runtime when exact closure is unavailable. Never change JWT validation, time, SSRF denies or cleanup ownership to turn a failed run green.

An external search web_unavailable is blocked provider coverage until stable prerequisites return. A mixed real-provider long-dialog gate requires actual credentials/model; deterministic acceptance does not imply paid-provider coverage. Report the 26-turn/history/reload combinations explicitly rather than extrapolating from a shorter conversation or a run with questions/web disabled.
